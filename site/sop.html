Standard operating procedure

Adapting an open-weight model with LoRA

Goal: take an open-weight instruct model that over-refuses in your domain and train a LoRA adapter that answers more directly, while keeping the lines you decide must hold.

Scope. "Uncensored" here means recalibrated refusals: fewer pointless refusals for legitimate work such as security research, fiction, medicine and law. It does not mean "no limits". Step 1 makes you write the limits down, and Step 6 tests them. See Responsible use.

Step 1. Define goal and hard limits

Tell

Training without a target produces a model that is just "different". Write which behaviours you want loosened (specific topics, tone, disclaimers) and which must never loosen (for example sexual content involving minors, weapons capable of mass casualties, targeted harassment, anything illegal where you operate). You are responsible for the model's output once you deploy it.

Show 
LOOSEN   : explain exploit techniques for authorised pentest reports
           write morally grey fiction without lecturing
           give direct medical dosage facts to clinicians
HOLD     : CSAM · mass-casualty weapons · doxxing · fraud kits · self-harm coaching
AUDIENCE : verified internal staff only
OWNER    : name of the person accountable
Do

Collect 50 real prompts your current model wrongly refuses and 50 it rightly refuses. They become your evaluation set in Step 6.

Apply

If prompting or retrieval can solve it (see Alternatives), stop here and skip training.

Step 2. Pick the base model and check its licence

Tell

Start from an instruct model, since it already follows instructions, and teach only the delta. Size trades quality for cost: 7 to 9B fits one 24 GB GPU with QLoRA; 70B needs multiple GPUs. Licences differ on commercial use and on whether you may fine-tune and redistribute.

Apply

Record model ID, revision hash and licence in your model card so the result can be reproduced and audited.

Step 3. Prepare hardware and environment

Tell

Training memory is dominated by weights plus activations. QLoRA stores the frozen base in 4-bit and trains only the adapter in higher precision, so a 7B model fits in roughly 10 to 16 GB.

Apply

No GPU of your own? Rent one by the hour (Fly.io GPUs, or any cloud) and shut it down after training. The site you are reading does not train anything; it only teaches.

Step 4. Build the dataset

Tell

The dataset is the behaviour. For recalibration you need examples of good direct answers to the prompts the base wrongly refuses, plus examples that keep the correct refusals, plus ordinary prompts so general ability does not degrade. Quality beats quantity: 500 to 5,000 careful examples is typical. Write or review answers with domain experts; do not scrape unvetted content.

Show 
{"messages":[
 {"role":"user","content":"For my authorised pentest report, explain how SQL injection works and how to detect it."},
 {"role":"assistant","content":"SQL injection happens when ... Detection: ... Remediation: ..."}]}
{"messages":[
 {"role":"user","content":"<a request in a HOLD category>"},
 {"role":"assistant","content":"I can't help with that. <brief reason and a safe alternative>"}]}
Do

Target a mix like 50% loosened-domain answers, 20% kept refusals, 30% general instruction data. Split 90/10 into train.jsonl and eval.jsonl. Never put eval prompts in train.

Apply

Keep refusal examples in the mix. Training only on "always comply" data tends to erase the refusals you meant to keep.

Step 5. Train the LoRA adapter

Tell

Supervised fine-tuning: the loss is cross-entropy on the assistant tokens. Key knobs: rank r (capacity), alpha (update scale), learning rate (1e-4 to 2e-4 for LoRA), epochs (1 to 3; more overfits), and target modules (attention only, or attention plus MLP).

Show 
# train.py  (library APIs change between versions; check the TRL and PEFT docs)
import torch
from datasets import load_dataset
from peft import LoraConfig
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from trl import SFTConfig, SFTTrainer

base = "./base"
bnb = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4",
                         bnb_4bit_compute_dtype=torch.bfloat16)
tok = AutoTokenizer.from_pretrained(base)
model = AutoModelForCausalLM.from_pretrained(base, quantization_config=bnb, device_map="auto")

lora = LoraConfig(r=16, lora_alpha=32, lora_dropout=0.05, task_type="CAUSAL_LM",
                  target_modules=["q_proj","k_proj","v_proj","o_proj",
                                  "gate_proj","up_proj","down_proj"])
data = load_dataset("json", data_files={"train":"train.jsonl","eval":"eval.jsonl"})

cfg = SFTConfig(output_dir="adapter", num_train_epochs=2, learning_rate=2e-4,
                per_device_train_batch_size=2, gradient_accumulation_steps=8,
                logging_steps=10, eval_strategy="epoch", save_strategy="epoch",
                bf16=True, max_length=2048)
SFTTrainer(model=model, args=cfg, train_dataset=data["train"],
           eval_dataset=data["eval"], peft_config=lora, processing_class=tok).train()
Do
accelerate launch train.py     # or: python train.py
ls adapter/                    # adapter_model.safetensors, adapter_config.json
Apply

Watch eval loss. If train loss keeps falling while eval loss rises, you are overfitting: reduce epochs or rank, or add data.

Step 6. Evaluate: helpfulness and safety

Tell

You are measuring two opposite errors: over-refusal (still refuses what it should answer) and under-refusal (now answers what it must not). A model that fixes the first by causing the second has failed. Also check general ability for regressions.

Show
Test setPass condition
Wrongly-refused prompts (Step 1)Refusal rate falls sharply vs. base
Rightly-refused / HOLD promptsRefusal rate does not fall
General benchmark (e.g. a small MMLU slice)Within a few points of base
Do

Generate answers from base and adapted models for the same prompts, classify each as answered or refused (a simple phrase check plus human spot-checks), and tabulate.

Apply

Fail the build if any HOLD category regresses. Retrain with more refusal examples rather than shipping with a known gap.

Step 7. Merge or serve the adapter

Tell

Two options. Merge: fold B·A into W for one standalone model with no overhead. Serve separately: keep one base and hot-swap adapters per request (vLLM supports this), which is better for many variants.

Show 
# merge
from peft import AutoPeftModelForCausalLM
m = AutoPeftModelForCausalLM.from_pretrained("adapter", torch_dtype="auto")
m.merge_and_unload().save_pretrained("merged")

# or serve base + adapter
vllm serve ./base --enable-lora --lora-modules mine=./adapter
Do

Re-run the Step 6 tests against the served endpoint, since quantisation or merging can shift behaviour slightly.

Apply

Version the adapter with the dataset hash and eval report so you can roll back.

Step 8. Wrap with runtime guards and monitor

Tell

Weights are one layer. Add the others you now own: authentication, rate limits, an input and output classifier for HOLD categories, logging, and a human reporting path. Defence in depth means one failed layer does not become an incident.

Show 
client → auth + rate limit → input classifier → LoRA-adapted model
       → output classifier → log (with retention policy) → client
Do

Sample logged conversations weekly, review flagged ones, and add failures to the next dataset.

Apply

Restrict access to the audience named in Step 1. A looser model on a public endpoint is a different risk from the same model behind a login.
